## Break fix, massé, Vietnamese (2026-10-04, Claude Code)
- **Weak break fixed.** Diagnosis (`PhysicsTraceDiagnostics.TraceBreakSpread`, writes `Temp/VTGPoolBridge/trace-break-spread.txt`): energy loss was physical (slide→roll ≈ 49 % of translational KE), but a *perfect* lattice rack channels the hard-sphere impulse along the 60° lines into the two back corners — only 3/15 balls moved > 30 cm. Fixes: `RackLayout.Jitter` (each racked ball ±0.3 mm, overlaps relaxed to ≥ 2R + 0.05 mm; `RackManager.rackJitter`) and `CueStrikeProfile.maxCueSpeed` 7 → 8 m/s (break ≈ 10.6 m/s). Result over 6 seeds: avg ≈ 0.76 m moved, ~10/15 balls > 30 cm, 0–3 pocketed. `PoolPhysicsSystem.LastStepBallCollisions` / `CollisionBudgetExhausted` added for diagnostics (budget never exhausted).
- **Massé / elevated cue.** `ShotParameters.CueElevation` (0–80°, `ShotRecord.CueElevation`). `CueStrikeModel` now uses the cue frame (d = aim·cosθ − up·sinθ, up' ⟂ d): impulse along d at r = R(a·right + b·up' − √(1−a²−b²)·d); ω = r×J/I; the slate absorbs the downward velocity (no jump shots). Level cue is bit-identical to before. Curvature comes from the existing cloth model (slip from the aim-axis spin). `CueBallSpinController.Elevation` (R / F keys via new `CueElevation` input action, `IShotInput.ElevationDelta`; C resets spin and elevation), HUD **elevation slider** left of the spin pad (`ElevationSlider`, shows "MASSÉ" ≥ 30°; works with touch), cue visual uses the same frame. `CuePathPredictor` (pure, steps `ClothFrictionModel`) draws the predicted **curved guide** when elevation ≥ 8° (`AimSystem.SetCurvedPath`), stopping at a ball / cushion / rest.

## Known issues / risks
- Presets are code-defined (`PhysicsTestPresetLibrary.CreateDefaults`); the setup's `assets` step overwrites the preset asset.
- Pocket holes are implemented by per-ball `Physics.IgnoreCollision` with the slate when the ball centre is over the hole (slate is a single box). Good enough for M1; a real mesh with holes may be wanted later.
- Ball-ball collisions use the custom swept `BallCollisionModel`; PhysX ball-ball layer pairs are disabled. Continue checking high-speed multi-ball breaks when tuning the solver.
- Cushion model suppresses vertical bounce (v.y = 0 after impact).
- Cue elevation (massé/jump) not modelled; cue visual is elevated only cosmetically.
- Camera Cinemachine API (CM 6.6.0 = CM3 lineage) compiled offline against the package; runtime blend behaviour unverified.
- Placeholder art (procedural textures, primitive table/cue).

## How to test (manual)
**Full game flow:** open `Assets/_PoolGame/Scenes/00_Bootstrap.unity` and press Play (or build): main menu → PLAY → choose game/opponent/AI level → START. In a match press P for the pause menu (Settings, Main menu, game switching). PRACTICE opens free practice (panel: Undo, Arrange balls, rack choice). Settings persist between sessions. To try the touch layout on desktop: Settings → Controls → Touch controls: On (drag the power slider with the mouse).

**Match (`02_Match`):** breaker starts with ball in hand behind the head string — move the mouse (or arrows/stick), click/Enter to place, then aim and shoot as below. After a foul the opponent gets ball in hand; press B to pick the cue ball up again before shooting. P / pause button = pause menu. Click the spin ball (bottom right) to set tip offset. Camera buttons bottom right.

**Physics test (`03_PhysicsTest`):**
Open `03_PhysicsTest`, Play.
- LMB-drag or A/D to aim (Shift = fine), arrows = tip offset (C = centre), hold Space for power and release to shoot, Enter = repeat last power.
- RMB-drag orbit, wheel zoom, 1/2/3 = Cue/Tactical/Top camera.
- F3–F12 or the left panel run presets; R re-lays the last preset; P pauses; F1 overlay; F2 velocity/spin vectors.
